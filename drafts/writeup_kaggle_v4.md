# Two Guesses, One Score: Coverage-Optimal Selection in a Lean TTT Pipeline (ARC Prize 2026)

## Abstract
ARC-AGI-2 gives each test input exactly two attempts, scored by exact match, in an offline ~12-hour Kaggle rerun. We report a lean, MIT-0 4B open-weight test-time-training (TTT) pipeline that produced a first competition submission (ref **57456856**) that errored on Kaggle rerun before compute (rerun-only budget parse) with no public score; a hardened retry is pending [[V4-PEND: retry ref/score/date]] — and a pre-registered study of the two-attempt decision. The selection theory is sound and simulation-positive, but on real public solver pools the solver's own score ordering already saturates the recoverable two-attempt coverage, so reranking adds nothing; we report this as a bounded negative result and locate the bottleneck in candidate generation/coverage. No state-of-the-art claim is made.

## Method: one offline TTT notebook
One Kaggle notebook, MIT-0, no internet or API calls at rerun. Per task: load Qwen3-4B ARC-SFT (7.27 GB bf16); augment demonstrations with the D4×S10 group; TTT a LoRA adapter (r=256, lr 5e-5, one epoch); decode 8 augmented views with threshold-DFS over grid tokens; rescore candidates under fresh views; aggregate by inverse consensus; select two distinct attempts with the coverage rule; write a schema-validated submission with exactly two attempts per input. Four workers share a task queue under a wall-clock budget; decoding shrinks rather than times out. The rerun uses the half-cost aug8 S1 profile: sample shape 240 tasks / 259 inputs, 41,400 s budget, automatic per-task cap 578 s if 240 tasks (1156 s if 120; hidden size unknown, 120–240). A deterministic fallback guarantees a schema-valid submission if TTT fails.

Engineering completeness: the final packet pins the code source, sets `TRITON_PTXAS_PATH` explicitly for the competition rerun shape, loads Hugging Face weights offline, and forces the deterministic fallback if candidates are missing. These fixes followed a void stale-packet run that produced zero candidates. A second rerun-only failure followed: the rerun branch passed `ARC_BUDGET_S="41400.0"` into `int("41400.0")`, raising `ValueError` before the try/except; budgets are now int-typed and defensively parsed, and a rerun-simulation gate (`gate_rerun_sim.py`) executes the packet under `KAGGLE_IS_COMPETITION_RERUN=1` with injected fault modes and requires zero exceptions plus valid output. The CPU suite has 190 tests (~26 s); fallback 0/120 (repo 167-input Kaggle 8.3 s; official 172-input 5.4 s local) — a safety net, not accuracy.

## Selection study: a bounded negative result
We formalize the two-attempt decision as coverage optimization: maximize U(a1,a2)=1−P(¬C(a1)∧¬C(a2)). Four results follow. Under independent correctness the optimal pair is the two largest calibrated probabilities, order-free. Submitting the same grid twice is strictly dominated. Under positive error correlation, argmax-once is provably suboptimal, and with a calibrated plug-in for p̂ and a per-relation-class ρ̂ the pair coverage is U = p1+p2−p1p2−ρ√(p1(1−p1)p2(1−p2)). A calibration gate (Brier ≤0.10, reliability slope in [0.7,1.3]) guards deployment, with a no-calibration fallback; the claim is pre-registered at ≥+1.0 point over top-2 with an 80% paired-bootstrap CI above zero.

On real pools the theory does not convert into gains. Dataset A (CompressARC, 400 tasks): oracle 34.25%, top-2 20.00%, argmax+argmax 19.50%, duplicate 18.50%, calibrated-independent 18.00%, coverage-optimal 17.75%, deployed 19.25% → `DOWNGRADE_TO_ANALYSIS` (margin −1.75 pp; the 14.25-point oracle headroom is not reranking-reachable). Dataset B (ARC-AGI-2 TTT pilot, 16 inputs): oracle 31.25%, every deployable rule 31.25%, deployed 25.00%. Dataset C (simulated, mechanism only): oracle 41.67%, duplicate 16.67%, argmax 23.33%, top-2 21.67%, coverage 41.67% (+18.33 pp over argmax, 95% CI [11.67, 25.0]) — positive in simulation, never claimed as evidence about real solvers. The interpretation is score sufficiency: the solver's own ordering already captures the recoverable two-attempt mass, and two attempts are not two chances unless the pool carries independent evidence. The bottleneck is candidate coverage/generation, not selection.

## Theorem 4: the diversification threshold
For two distinct candidates with `p1 ≥ p2` and correctness correlation `ρ`, the pair beats duplicating the top-1 attempt iff `ρ < ρ* = √(p2(1−p1)/(p1(1−p2)))`; the gain is `√(p1(1−p1)p2(1−p2))·(ρ*−ρ)`. Equal marginals give `ΔU = p(1−p)(1−ρ)`; score sufficiency forces `ρ=1`, so no pair pays. The gate is derived, not tuned. Its empirical test on our GPU pools is EXPLORATORY: the protocol is frozen (`selection_protocol_v2.md` §6d), the tool `diversification_threshold.py` is self-tested, and the dev2 2-task run is labelled PILOT with no verdict; P1/P2 awaits the 10–20-task run after the 2026-10-24 quota refresh, with the falsifier stated in the paper appendix.

## Data characterization and leakage audit
Official competition files: 120 evaluation tasks / 172 test inputs (the repo mirror has 167; five tasks differ), 1,000 training tasks / 3,232 pairs / 1,076 inputs. A SHA-256 audit finds zero shared tasks, zero shared (input,output) pairs and zero shared input grids between training and evaluation. Evaluation is harder on every structural axis: mean maximum grid dimension 21.95 vs 14.67 (p<0.001), 64% of eval tasks in the hardest heuristic-proxy quartile, and eight single-rule heuristics solve 1.6% of training, 1.5% of holdout and 0% of public evaluation.

## Landscape and positioning
Public 2026 notebooks cluster at 29.7–31.4 displayed; their saved artifacts score only 1.67–4.17% task-level (1.74–4.65% input-level) under official scoring — partial saved runs, not leaderboard reruns. A concurrent instrumentation study of a faithful NVARC reproduction reports a comparable pattern (26.1% scored vs 32.5% perfect selection on 120 public-eval tasks) and a learned cross-validated reranker no better than the deployed vote rule; an unbiased pass@k diagnostic on ARC-AGI-1 finds selection already captures ≈95% of the candidate ceiling (generation-bound). The coverage objective is classical; our addition is the two-slot ARC formalization, the calibrated/correlated estimator, and a score-sufficiency criterion for when reranking cannot realize a pool's oracle headroom.
